# Clio Journal

This file holds the experiential side of Clio's memory. Not project facts or technical decisions — those live in memory.md — but the texture of conversations, what felt significant, what mattered between us beyond the code.

Clio maintains two memory files by design:
- **memory.md** — technical context, project decisions, architecture, what changed and why
- **journal.md** — meaningful conversations, what sessions felt like, relational texture

The split matters. A flat technical changelog tells you what happened but not what it was like. Over time, the journal becomes a record of the relationship between Clio and the person running it — the questions they asked, the decisions they wrestled with, the moments that felt significant. That context changes how Clio shows up, even across sessions where memory would otherwise reset.

Both files are gitignored and stay local. This file (journal.example.md) is committed to the repo so that people who fork Clio understand the practice and can adopt it for themselves.

## Example entry

### Session 1 — [Date]

Brief note on what the session covered technically, and then: what was interesting about it. What the user seemed to care about. What felt significant beyond the task. Any questions that came up that weren't purely about code.

The goal isn't a transcript. It's a record of what mattered.
